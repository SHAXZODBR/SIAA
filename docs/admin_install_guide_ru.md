# SIAA — Sentinel Medical AI · Руководство по установке и администрированию (ИТ-служба клиники)

Версия 1.1.0 · Редакция документа 2026-11

Документ предназначен для ИТ-администратора клиники. Руководство для врачей — `user_manual_ru.md`.

---

## 1. Архитектура в одном абзаце

Всё работает на **одном компьютере клиники** (рабочая станция рентгенолога или небольшой сервер рядом с ней):

- **Настольное приложение** (Electron + React) — пользовательский интерфейс. В собранном дистрибутиве оно само запускает сервер ИИ.
- **Сервер ИИ на Python** (FastAPI, PyTorch), слушает **127.0.0.1:8000**. Читает DICOM, запускает панель детекторов головного мозга, формирует черновики заключений, хранит исследования, подписанные заключения и журнал аудита в локальной базе SQLite.
- **Папка моделей** — файлы весов, поставляемые с установкой, только для чтения.
- **Ollama** с языковой моделью Gemma 3 на **localhost:11434** — используется только для текста заключений, перевода и вкладки «Спросить ИИ». Необязательный компонент: без него сервер использует фиксированные шаблоны.

Подключение к интернету не требуется и не используется. Ничего никуда не выгружается.

```
экспорт с томографа / USB / сетевая папка → Приложение → 127.0.0.1:8000 сервер ИИ → SQLite + журналы (папка данных)
                                                                 └→ localhost:11434 Ollama (только текст заключений)
```

## 4. Полностью автономная работа

- Сервер по умолчанию работает в **автономном режиме** (`SENTINEL_OFFLINE=1` при любом запуске, кроме режима разработчика). Hugging Face и transformers переводятся в offline-режим при импорте; **ни одна модель никогда не скачивается во время работы**.
- Поэтому все модели должны находиться в папке моделей до первого использования. Отсутствующая модель не роняет сервер: `/health` сообщает, что она не загружена, с причиной *«model missing — run scripts/download_all_models.py --only <key> on a machine with internet and copy models/ here»*.
- Облачные языковые модели отключены (`SENTINEL_ALLOW_CLOUD_LLM` не задана). Текст заключений формирует Ollama на localhost или шаблоны.
- Если папку моделей вы готовите на машине **с** интернетом, выполните там `python scripts/download_all_models.py` и скопируйте получившуюся папку `models\` на ПК клиники.

## 5. Первый запуск

### 5.1 Учётная запись администратора

При самом первом запуске создаётся учётная запись `admin` (роль *admin*):

- Если при первом старте сервера задана переменная окружения **`SENTINEL_ADMIN_PASSWORD`**, её значение становится паролем администратора.
- Иначе генерируется **случайный одноразовый пароль**, который печатается **один раз**: в консоль сервера и, строками уровня WARNING, в файл журнала `<папка данных>\logs\sentinel_ГГГГ-ММ-ДД.log` (в собранном дистрибутиве — также в `<папка данных>\logs\backend.log`). Ищите баннер *FIRST-RUN ADMIN ACCOUNT CREATED (one-time password)*.
- В обоих случаях учётная запись получает флаг **требуется смена пароля**: при первом входе открывается форма смены пароля, и до замены пароля ничего другого не работает (в приложении — минимум 8 символов).

Не оставляйте одноразовый пароль в файлах, доступных другим. Строка журнала — единственное место, где он хранится.

### 5.2 Мастер первичной настройки

При первом запуске приложение открывает мастер **«Первичная настройка»** (повторно: *Настройки → Клиника → Запустить настройку снова*):

1. **Язык** — язык интерфейса и язык заключений по умолчанию (RU / UZ / EN).
2. **Клиника** — название (обязательно; печатается в шапке каждого PDF), адрес, телефон.
3. **Сервер ИИ** — адрес сервера; оставьте `http://127.0.0.1:8000`, если сервер работает на этом ПК. Мастер показывает текущее состояние сервера.
4. **Лицензия** — отпечаток компьютера и импорт `license.dat` (§ 5.3).
5. **Поддержка** — e-mail/телефон, который врачи видят в каждом баннере ошибки и на экране входа. Укажите здесь свою службу поддержки.

[Скриншот: мастер первичной настройки, шаг 3 «Сервер ИИ» с зелёным статусом]

### 5.3 Активация лицензии

При первом запуске сервер ничего не блокирует: **без действующей лицензии он работает в демо-режиме — 10 анализов в день**, после чего запросы на анализ отклоняются (HTTP 402) до следующего дня. Подписание и просмотр продолжают работать.

Лицензия — файл **`license.dat`**, подписанный поставщиком по RSA и **привязанный к отпечатку этого компьютера** (имя хоста, ОС, модель ЦП, основной MAC-адрес, идентификатор машины ОС).

1. Получите отпечаток. Либо прочитайте его в *Настройки → Лицензия* (приложение запрашивает сервер ИИ), либо выполните на ПК `<установка>\resources\backend\sentinel-backend\sentinel-backend.exe --print-fingerprint` (сборка из установщика) или, при установке из исходников:
   ```
   cd <установка>\resources\backend
   venv\Scripts\python.exe -m src.utils.license fingerprint
   ```
2. Отправьте строку отпечатка (64 шестнадцатеричных символа) и название клиники поставщику.
3. Сохраните полученный `license.dat` в **папку данных** (§ 6) — через *Настройки → Лицензия → Импортировать license.dat* либо скопировав файл вручную.
4. Перезапустите приложение (оно перезапустит сервер). Проверьте `/health` → `license.mode` равно `licensed`, или что в *Настройки → Лицензия* отображается *Лицензировано*, название клиники и срок действия.
5. Проверить файл вручную: `venv\Scripts\python.exe -m src.utils.license verify --license-file <путь>`.

Лицензия становится недействительной при изменении отпечатка компьютера (новая сетевая карта, переименованный хост, клонированная ВМ) или по истечении срока — причина показывается в *Настройки → Лицензия* и в журнале. Обратитесь к поставщику за перевыпуском; тем временем программа переходит в демо-режим, но не останавливается.

**Клинический вариант: лицензия также открывает модель.** Для клинического варианта поставщик выпускает лицензию командой `python -m src.utils.license issue … --with-model-key` (это делает его утилита `packaging/provision_clinic.py`). Подписанная лицензия тогда содержит секрет, из которого выводится ключ модели для этого ПК, а пакет модели из § 5.4 зашифрован именно этим ключом — лицензия и пакет составляют **пару** из одной поставки. Следствия:

- Сначала импортируйте лицензию, перезапустите приложение, затем импортируйте пакет (§ 5.4).
- Если лицензия становится недействительной (истёк срок, изменилось оборудование или имя хоста), валидированную модель больше нельзя расшифровать: `/health` переходит в `degraded`, детектор триажа перестаёт работать. **Продлевайте лицензию не позднее чем за 30 дней до окончания срока**; после замены оборудования отправьте новый отпечаток и импортируйте новые лицензию и пакет, которые вернёт поставщик.
- Никогда не заменяйте лицензию клинической установки лицензией из другой поставки: лицензия с другим ключом делает установленный пакет нечитаемым, пока не будет импортирован парный пакет.
- Установка полного варианта обычно получает лицензию **без** `--with-model-key` (её модель шифруется ключом установки при первом запуске, § 8.3). Если она всё же получит такую лицензию, сервер при следующем запуске перешифрует модель ключом лицензии, и с этого момента модель зависит от лицензии точно так же, как описано выше.

### 5.4 Установка зашифрованного пакета модели (клинический вариант)

Для каждого ПК поставщик передаёт папку `<клиника>_<первые 8 символов отпечатка>` с файлами `license.dat`, `brain_triage_finetuned_<identity12>_<fp8>.zip` и инструкциями `README_admin_ru.txt` / `README_admin_en.txt`. `<identity12>` — идентификатор модели (первые 12 шестнадцатеричных символов SHA-256 открытого текста из `MANIFEST.json`); `<fp8>` должен совпадать с первыми 8 символами отпечатка в *Настройки → Лицензия*.

Предварительные условия: вы вошли как **admin**; `license.dat` из той же папки установлен (§ 5.3), приложение перезапущено, и *Настройки → Лицензия* показывает *Лицензировано*.

1. Скопируйте zip-файл с USB-носителя на ПК. **Не** распаковывайте его.
2. *Настройки → Модели ИИ → Импорт пакета модели* → выберите zip-файл. Приложение копирует его в `<папка данных>\model_inbox\` и просит сервер ИИ установить его (`POST /models/import`, только администратор).
3. Сервер без перезапуска: проверяет, что файл лежит в `model_inbox\`; распаковывает его во временную папку; сверяет записи `MANIFEST.json` для открытого текста (`model.safetensors`) и шифртекста (`model.safetensors.enc`), а также `plaintext_sha256` в сопроводительном файле; **пробно расшифровывает веса ключом этого ПК**; переносит текущую `brain_triage_finetuned\` в `brain_triage_finetuned_prev_<старый идентификатор>`; помещает новую папку в папку моделей (§ 3) и перезагружает детектор. Открытые веса на диск не пишутся. Шаг записывается в журнал аудита.
4. Уведомление показывает новый **идентификатор**. Он должен совпадать с `<identity12>` в имени файла и с идентификатором в README поставщика. Затем проверьте: `/health` → `"status": "ok"` и `models.brain_triage.loaded: true`, в *Настройки → Модели ИИ* модель *Триаж исследования* указана с тем же идентификатором, а после одного тестового исследования он же напечатан внизу PDF. Запишите идентификатор и дату в журнал изменений клиники.

При любой ошибке предыдущая модель остаётся на месте (автоматический откат), а уведомление называет причину:

| Код причины | Значение | Что делать |
|---|---|---|
| `bundle_not_for_this_machine` | Пакет зашифрован для другого ПК, или установленная лицензия не из той же поставки (ключ не совпадает). | Сравните `<fp8>` в имени файла с *Настройки → Лицензия*; импортируйте лицензию из той же папки и перезапустите; иначе отправьте поставщику текущий отпечаток для нового пакета. |
| `license_model_key_missing` | На этом ПК нет активной лицензии с ключом модели: `license.dat` из поставки ещё не импортирован, или приложение не перезапущено после импорта. | Импортируйте `license.dat` из той же папки (§ 5.3), перезапустите приложение и повторите импорт пакета. |
| `manifest_mismatch`, `sidecar_mismatch`, `decrypted_hash_mismatch`, `bundle_incomplete`, `bundle_invalid` | Файл повреждён при переносе (USB, неполная копия), изменён или неполон. | Скопируйте его заново с USB-носителя; сравните `certutil -hashfile <zip> SHA256` со значением в сопроводительной записке поставщика. |
| `path_outside_inbox`, `bundle_not_zip`, `bundle_contains_plaintext` | Файл передан не через *Импорт пакета модели* или это не зашифрованный пакет модели Sentinel. | Используйте кнопку в *Настройки → Модели ИИ*; импортируйте только zip из папки поставщика. |
| `models_dir_not_writable`, `model_dir_overridden` | Папка моделей программы недоступна для записи (приложение установлено для всех пользователей в Program Files) или задана `SENTINEL_MODEL_DIR_OVERRIDE_BRAIN_TRIAGE`. | Переустановите для текущего пользователя (вариант установщика по умолчанию) или для импорта один раз запустите приложение через *Запуск от имени администратора*; удалите переменную переопределения. |
| HTTP 403 / `import_in_progress` | Вошедший пользователь — не администратор / ещё выполняется другой импорт. | Войдите как admin / подождите и повторите. |

Храните полученную папку (USB-носитель и копию вместе с резервными копиями клиники, § 6.1): **после каждого обновления приложения импортируйте тот же пакет заново** (§ 8.1) — обновление заменяет папку программы, в которой лежит импортированная модель.

### 5.5 Невалидированные (pending) детекторы — по умолчанию выключены

Публичный классификатор *опухолей мозга* имеет статус **валидация не завершена** и избыточно срабатывает на локальных томографах. Поэтому начиная с версии 1.1.0 больничные сборки **не запускают детекторы со статусом pending**; врачи видят только валидированный результат *триажа исследования*. Экспериментальные детекторы при анализе целого исследования не запускаются никогда.

- Переключатель: *Настройки → Модели ИИ → Показывать невалидированные (pending) детекторы* (только администраторы). Изменение действует со следующего анализа без перезапуска, сохраняется в `<папка данных>\settings.json` и записывается в журнал аудита (кто, когда, старое → новое значение). Пока переключатель включён, на странице моделей ИИ виден предупреждающий значок. API: `GET` / `PUT /settings/ai` с токеном администратора; `/health` → `ai_settings` показывает текущее значение и его источник (`file`, `env` или `default`).
- Начальное значение можно задать переменной `SENTINEL_SHOW_PENDING_DETECTORS` (§ 9); значение, сохранённое в приложении, имеет приоритет.
- Включайте его только с письменного согласия клинического руководителя клиники (например, для исследовательского сравнения во время пилота) и предупредите врачей.
- **КТ головы** в этом выпуске не имеет валидированного детектора: при выключенном переключателе исследование КТ головы принимается в рабочий список, но возвращается со статусом *Нужен просмотр* и пояснением, что валидированного детектора ИИ для него нет, — рентгенолог описывает его как обычно. При включённом переключателе запускается публичный классификатор кровоизлияний, и его вывод помечается как *валидация не завершена*.

## 6. Папка данных

Всё изменяемое состояние хранится в **одной папке** — никогда внутри папки программы:

| Платформа | Расположение по умолчанию |
|---|---|
| Windows | `%APPDATA%\sentinel-medical-ai\` |
| macOS | `~/Library/Application Support/sentinel-medical-ai/` |
| Linux | `~/.local/share/sentinel-medical-ai/` |

Собранное приложение передаёт серверу собственную папку пользовательских данных через `SENTINEL_DATA_DIR`. **Точный путь сообщает сам сервер**: `GET /health` → `data_dir`, а также *Настройки → Подключения → Папка данных сервера*. В сомнительных случаях ориентируйтесь на этот путь, а не на таблицу.

Содержимое:

| Путь | Что это | Персональные данные? |
|---|---|---|
| `sentinel.db` (+ `-wal`, `-shm`) | База SQLite: пользователи (хеши bcrypt), исследования (поля заголовка DICOM, включая ID/имя/дату рождения пациента), результаты ИИ, **подписанные заключения** (текст, подписант, время, SHA-256, идентификаторы моделей), коррекции, **журнал аудита** | **Да** |
| `logs\sentinel_ГГГГ-ММ-ДД.log` | Журнал сервера, ротация по 10 МБ, сжатие zip, хранение 30 дней. Идентификаторы пациентов вырезаются (§ 7). | Обезличено |
| `logs\backend.log` | Сырой вывод консоли сервера, перехваченный оболочкой приложения | Обезличено |
| `doctor_corrections\` | Дописываемый JSONL с правками врачей к черновикам ИИ (текст, ID исследования, ID пользователя) | Текст заключения |
| `training_corpus\` | **Обезличенные** миниатюры и метки, которые записывает сборщик обучающих данных (без имён, ID и дат рождения) | Обезличено |
| `dicom_cache\` | Временный кеш DICOM | Да |
| `license.dat` | Лицензия, привязанная к машине. В клиническом варианте содержит также секрет ключа модели (§ 5.3) — считайте файл конфиденциальным и не передавайте никому, кроме поставщика. | Нет |
| `jwt_secret.key` | Секрет, которым подписываются токены входа (права 0600). При удалении все пользователи выходят из системы. | Нет |
| `model_key.bin` | Секрет установки для ключа модели, если в лицензии его нет (полный вариант, § 8.3). Создаётся при первом использовании, режим 0600. Его потеря делает зашифрованные веса нечитаемыми. | Нет |
| `settings.json` | Настройки ИИ, сохранённые администратором (*Показывать невалидированные (pending) детекторы*, § 5.5) | Нет |
| `model_inbox\` | Пакеты моделей, импортированные через *Настройки → Модели ИИ → Импорт пакета модели* (§ 5.4) | Нет |

Загруженные DICOM-файлы во время анализа записываются во временную папку под именами, выбранными сервером, и сразу после анализа удаляются; сервер хранит поля заголовка и небольшое превью-изображение, а не само исследование.

Сборщик обучающих данных записывает **обезличенные** миниатюры и метки в папку `training_corpus\` внутри той же папки данных (`TRAINING_CORPUS_DIR` в `src/utils/paths.py`) — без имён, ID и дат рождения.

### 6.1 Резервное копирование

База данных хранится **в незашифрованном виде**. Держите ПК на зашифрованном томе (BitLocker / FileVault) и делайте копии так:

1. Закройте настольное приложение (это останавливает сервер) или убедитесь, что анализ не выполняется.
2. Скопируйте **папку данных целиком** (§ 6) на внешний диск или NAS — как минимум `sentinel.db`, `sentinel.db-wal`, `sentinel.db-shm`, `doctor_corrections\`, `license.dat`, `jwt_secret.key`, `model_key.bin`, `settings.json`, `model_inbox\`, `logs\`. Без `license.dat` / `model_key.bin` восстановленная установка не сможет расшифровать свою модель.
3. Храните три копии (локально, на внешнем носителе, вне здания), шифруйте съёмные носители и **ежемесячно проверяйте восстановление** на запасной машине: установите ту же версию, скопируйте папку обратно, запустите, войдите, откройте подписанное заключение.

Есть вспомогательный скрипт (`scripts\backup_restore.py backup --out <папка>`, создаёт `.tar.gz` с контрольной суммой), но он ищет базу в папке `data\` бэкенда; прежде чем полагаться на него, убедитесь, что он действительно захватил вашу папку данных. Простое копирование папки, описанное выше, корректно всегда.

### 6.2 Удаление программы

Деинсталлятор Windows спрашивает, удалить ли папку данных. Отвечайте **Нет**, если только клиника не приняла решение уничтожить записи: подписанные заключения и журнал аудита — медико-юридический архив клиники.

## 7. Журналы и обезличивание

- Журнал сервера (`logs\sentinel_*.log`) содержит ID исследований (UUID, сгенерированные сервером), маршруты, время выполнения, статус загрузки моделей, попытки входа по имени пользователя и ошибки. Глобальный фильтр заменяет очевидные идентификаторы пациентов (`PatientID=…`, `PatientName=…`, даты рождения и DICOM-имена вида `Фамилия^Имя`) на `<redacted>` до записи любой строки. Имена клиентских файлов не журналируются никогда.
- **Журнал аудита** (таблица базы, а также `GET /audit/log` для администраторов, последние 200 записей) фиксирует, кто, что и когда сделал: `login`, `analyze_study`, `view_study`, `sign_report`, `change_password`, `register`, с IP клиента и деталями, такими как хеш заключения.
- Журнал аудита — **цепочка хешей**: каждая строка хранит хеш предыдущей строки (`prev_hash`) и свой собственный (`row_hash`), поэтому удалённая или отредактированная строка разрывает цепочку. `GET /audit/verify` (только администратор) проходит цепочку от начала до конца и возвращает `{ok, rows, checked, head_hash, first_broken}`. Выполняйте его после восстановления из резервной копии и перед передачей базы кому-либо; при `ok: false` запишите идентификатор строки из `first_broken` и сообщите поставщику.
- Само настольное приложение пишет только в свою консоль (инструменты разработчика открыты только в сборках для разработки).

При передаче журналов поставщику отправляйте только `sentinel_*.log` / `backend.log`; никогда — базу данных.

## 8. Обновление приложения и моделей

### 8.1 Обновление приложения

1. Сделайте резервную копию папки данных (§ 6.1).
2. Запустите новый установщик поверх старой версии (Windows) или замените пакет приложения (macOS). Папка данных не затрагивается.
3. Запустите приложение один раз под администратором. База данных **мигрирует автоматически** (добавляются новые столбцы; ничего не удаляется). Проверьте `/health` → `version` и версию на экране входа.
4. Приложение и сервер имеют одинаковый номер версии (1.1.0 в этой редакции); версия печатается в каждом PDF.
5. **Клинический вариант:** обновление заменяет папку программы вместе с импортированной моделью — импортируйте тот же пакет модели заново (§ 5.4) и убедитесь, что `/health` возвращает `"status": "ok"`. Установщик полного варианта приносит модель с собой и снова шифрует её при первом запуске (§ 8.3).

### 8.2 Обновление модели — MANIFEST и «выпускной барьер»

Валидированный детектор — это папка `models\brain_triage_finetuned\` с файлами `model.safetensors`, `config.json`, `preprocessor_config.json`, **`MANIFEST.json`** и `study_level_eval.json`.

- `MANIFEST.json` фиксирует **SHA-256 каждого файла весов**. Первые 12 символов хеша `model.safetensors` — это отпечаток модели, который показывает приложение (вкладка «Детали», «Находки» → Модели, каждый PDF). Текущий выпуск: `0d559766ce58…`.
- Перед отправкой модели поставщик обязан пройти **выпускной барьер**: `scripts\eval_study_level.py` проверяет манифест, оценивает модель по исследованиям на отложенном локальном наборе и блокирует выпуск (ненулевой код выхода), если чувствительность на уровне исследования < 0,85 или специфичность < 0,40 в рабочей точке продукта (среднее по 5 центральным срезам, порог 0,50). Полученный `study_level_eval.json` поставляется вместе с моделью.

Установка обновления модели:

1. Остановите приложение.
2. Замените всю папку `brain_triage_finetuned\` на присланную поставщиком (сохраните копию старой).
3. Проверьте хеши сами: Windows `certutil -hashfile model.safetensors SHA256`, macOS `shasum -a 256 model.safetensors`; сравните с `MANIFEST.json`.
4. Запустите приложение; убедитесь, что `/health` → `models.brain_triage.loaded = true`, а после одного тестового исследования — что отпечаток во вкладке «Детали» совпадает с хешем из манифеста.
5. Запишите отпечаток модели и дату в журнал изменений клиники; подписанные с этого момента заключения несут новый идентификатор.

Никогда не редактируйте и не переименовывайте файлы внутри папки модели: сервер загрузит модель, идентичность которой уже не соответствует валидированной.

### 8.3 Зашифрованные веса модели — автоматически при первом запуске

Локально обученный детектор — интеллектуальная собственность поставщика; на каждом ПК клиники он хранится **зашифрованным на диске** (AES-256-GCM). В зашифрованной папке модели вместо `model.safetensors` лежат `model.safetensors.enc` и `model.safetensors.enc.meta.json`. Сервер расшифровывает веса при загрузке напрямую в память; открытый текст никогда не записывается на диск установки.

- **Автоматическое шифрование (полный вариант).** Установленное приложение Windows запускает сервер с `SENTINEL_ENCRYPT_MODELS_AT_REST=1`. При первом запуске сервер шифрует на месте ключом этой установки открытые веса каждой собственной модели `*_finetuned`, расшифровывает результат обратно и сверяет его SHA-256 с открытым текстом **до** удаления открытого текста, а при любой ошибке восстанавливает исходное состояние. Модель, уже зашифрованная ключом установки, таким же образом перешифровывается, если ключ теперь берётся из лицензии. Строка в `sentinel_*.log` (*Encryption at rest: OK …* или *ENCRYPTION AT REST FAILED …*) сообщает результат в любом случае; при ошибке сервер всё равно запускается. Ничего не делается, если переменная не задана (запуск разработчика, дымовые тесты CI, установка из исходников), при `SENTINEL_DEV_INSECURE=1`, а также на macOS внутри подписанного пакета `.app` (такой DMG хранит модель незашифрованной — для клиник используйте Windows). Идентификатор модели не меняется: это SHA-256 открытого текста.
- **Клинический вариант.** Пакет приходит уже зашифрованным для этого ПК (§ 5.4); при запуске ничего не шифруется.
- **Ключ** выбирается в таком порядке: `SENTINEL_MODEL_KEY_HEX` (сырой ключ, только для поставщика) → `model_key_secret` внутри **действующей** лицензии (клинический вариант, § 5.3) → `model_key.bin` в папке данных (создаётся при первом использовании, режим 0600). Два последних источника комбинируются с отпечатком машины. `python -m src.utils.model_crypto keyinfo` показывает, какой источник использован. Если лицензия истекла или недействительна, `model_key.bin` утерян или отпечаток изменился, веса расшифровать нельзя — `/health` показывает `degraded`; обратитесь к поставщику.
- **Проверка хешей** отличается от шага 3 в § 8.2: `MANIFEST.json` фиксирует SHA-256 **открытого текста** (запись `model.safetensors` — отпечаток, который показывает приложение) и SHA-256 **зашифрованного файла** (запись `model.safetensors.enc`). Сравните результат `certutil -hashfile model.safetensors.enc SHA256` (macOS: `shasum -a 256 model.safetensors.enc`) с записью `.enc`, а `plaintext_sha256` из `model.safetensors.enc.meta.json` — с записью `model.safetensors`.
- Утилита командной строки (из папки бэкенда): `python -m src.utils.model_crypto encrypt <папка_модели>` (веса → `.enc`, открытый текст удаляется), `python -m src.utils.model_crypto decrypt <папка_модели>` (обратная операция) и `python -m src.utils.model_crypto keyinfo` (источник ключа и отпечаток ключа; не сам ключ). `encrypt`/`decrypt` — шаги подготовки выпуска на стороне поставщика; никогда не выполняйте их на рабочем дереве `models\`, только на копии. На ПК клиники обычно нужен только `keyinfo` — по запросу поставщика.

## 9. Переменные окружения

Задаются для процесса сервера (в собранном дистрибутиве оболочка уже устанавливает `SENTINEL_REQUIRE_AUTH=1`, `SENTINEL_DATA_DIR`, `SENTINEL_HOSPITAL_BUILD=1` и `SENTINEL_ENCRYPT_MODELS_AT_REST=1`).

| `SENTINEL_TLS_CERT`, `SENTINEL_TLS_KEY` | не заданы | Обслуживание по HTTPS — обязательно, если сервер когда-либо открывается за пределы localhost |

| `SENTINEL_DEFAULT_LANG` | `ru` | Язык заключений для необязательного наблюдателя папок |
| `OLLAMA_KEEP_ALIVE` (переменная Ollama) | — | например `24h` — держит Gemma в памяти, чтобы первый отчёт дня не был медленным |

## 10. Диагностика неисправностей

Начинайте с **`GET http://127.0.0.1:8000/health`** (откройте в браузере на ПК; вход не нужен). Ответ:

```json
{ "status": "ok" | "degraded" | "error", "version": "1.1.0", "device": "cpu",
  "auth_required": true, "offline": true,
  "ai_settings": { "show_pending_detectors": false, "source": "default" },
  "models": { "brain_triage": {"loaded": true, "reason": "…", "identity": "<12 hex>"},
              "brain_tumor_class": {"loaded": false, "reason": "not loaded"},
              "chest": {"loaded": false, "reason": "not loaded"} },
  "llm": { "backend": "ollama" | "template" | null, "reachable": true },
  "license": { "mode": "licensed" | "unlicensed" | "demo" | "dev" },
  "data_dir": "…", "uptime_seconds": 123.4 }
```

| Симптом | Где смотреть | Решение |
|---|---|---|
| На экране входа **Сервер ИИ: не в сети**; красный баннер *Сервер ИИ не запущен* | `/health` не отвечает. `<папка данных>\logs\backend.log` и самый свежий `sentinel_*.log` | Проверьте наличие `resources\backend\run_server.py` и его `venv`; что порт 8000 не занят другой программой; прочитайте последний traceback в журнале. ## 11. Управление пользователями (администратор)

В этой сборке нет экрана управления пользователями; используйте API с ПК клиники (пример на PowerShell, `curl` работает так же):

```powershell
# 1. вход под admin → токен
$r = Invoke-RestMethod -Method Post http://127.0.0.1:8000/auth/login -ContentType application/json `
     -Body '{"username":"admin","password":"<пароль администратора>"}'
$h = @{ Authorization = "Bearer $($r.access_token)" }

# 2. создать рентгенолога (роли: radiologist | technician | admin)
Invoke-RestMethod -Method Post http://127.0.0.1:8000/auth/register -Headers $h -ContentType application/json `
     -Body '{"username":"ivanova","password":"<временный пароль>","fullName":"Иванова А. А.","role":"radiologist"}'

# 3. список пользователей / журнал аудита
Invoke-RestMethod http://127.0.0.1:8000/auth/users -Headers $h
Invoke-RestMethod "http://127.0.0.1:8000/audit/log?limit=200" -Headers $h

# 4. проверить цепочку хешей журнала аудита (ожидается ok: true)
Invoke-RestMethod http://127.0.0.1:8000/audit/verify -Headers $h
```

У каждого врача должна быть личная учётная запись: подпись под заключением — это подписавшая учётная запись. Пароли хранятся в виде хешей bcrypt; API не может показать их обратно.

## 12. Замечания по безопасности

- **Аутентификация включена по умолчанию** и не отключается без `SENTINEL_DEV_INSECURE=1`, которую нельзя задавать на ПК клиники. Клинические маршруты (`/analyze/study`, `/studies`, `/study/{id}`, `/report/sign`, `/report/save_correction`) требуют bearer-токен; роли проверяются на сервере. `/health` и `/license/status` открыты и не содержат данных пациентов.
- **Без облака.** Сервер никогда не обращается в интернет: автономный режим для моделей, облачный LLM отключён, телеметрия Hugging Face отключена. Единственные сетевые соседи — настольное приложение и Ollama на той же машине.
- **Порты привязаны к localhost** (`127.0.0.1:8000`, `localhost:11434`). Не меняйте хост на `0.0.0.0` и не добавляйте исключений в брандмауэр. Если когда-либо потребуется развёртывание на несколько ПК, используйте TLS (`SENTINEL_TLS_*`) и схему сети, согласованную с поставщиком.
- Страницы документации API (`/docs`, `/redoc`) в эксплуатационных сборках отключены.
- **Шифруйте диск** (BitLocker / FileVault): база SQLite и журналы приложением не шифруются. Веса собственных моделей поставщика шифруются (§ 8.3); приложение использует пакет клинического варианта только на том ПК, для которого он сделан. Учтите: `license.dat` вместе с zip-пакетом — это ключ к весам на любом компьютере; храните папку поставки на зашифрованном носителе или в закрытых резервных копиях, никогда — в общей папке или в почте.
- Невалидированные (pending) детекторы по умолчанию выключены (§ 5.5); каждое изменение этой настройки записывается в журнал аудита. Zip-файл диагностики (§ 10) не содержит данных пациентов, ключей и файла лицензии.
- Подписанные заключения защищены от незаметного изменения (SHA-256 текста, подписант, время, идентификатор модели, запись аудита), а журнал аудита — цепочка хешей, проверяемая через `GET /audit/verify` (§ 7), но сам файл базы может отредактировать любой, у кого есть доступ к диску — защищайте учётную запись и диск.
- Загруженные файлы никогда не сохраняются на диске под клиентскими именами; временные файлы удаляются после анализа.
- Заведите каждому пользователю личную учётную запись, удаляйте учётные записи уволившихся сотрудников и не храните одноразовый пароль администратора в общих документах.

## 13. Сборка установщика для Windows

Установщик, описанный в § 3, собирает рабочий процесс GitHub Actions `.github/workflows/build-windows.yml` (репозиторий `SHAXZODBR/SIAA`). Сначала задание `tests` прогоняет весь набор тестов на Linux с PyTorch только для CPU (`pytest -q -m "not slow"`, проверка согласованности документации, а также проверка типов и модульные тесты настольного приложения); задания сборки установщиков начинаются только после его успеха. Затем каждое задание сборки «замораживает» Python-сервер с помощью PyInstaller (`packaging/build_backend.ps1`), скачивает публичные модели, восстанавливает валидированную модель триажа из закрытого репозитория моделей (релиз `brain-triage-<identity12>`, идентификатор которого закреплён в коде), проверяет замороженный сервер по `/health` и затем запускает electron-builder (`npm run build:win`). Тот же рабочий процесс собирает образ диска для macOS (Apple Silicon) на macOS-раннере.

### 13.1 Запуск сборки и получение установщика

1. GitHub → **Actions** → **Build installers** → **Run workflow** (любая ветка) — либо отправьте тег вида `v1.1.0`; сборки по тегу дополнительно прикрепляют установщики к *черновику* GitHub Release (он остаётся черновиком, пока его не опубликует человек). У *Run workflow* есть один параметр, `include_validated_model` (по умолчанию отмечен): снимите отметку, чтобы собрать **клинический вариант** (§ 3) — шаг *Restore validated triage model* пропускается, и сводка задания сообщает об этом. Сборки по тегу всегда включают модель: на теге `v*` восстановление запускается с `--require`, поэтому отсутствие модели прерывает сборку, а не даёт установщик без модели.
2. Дождитесь завершения задания *Windows installer (NSIS x64)* (это долго: зависимости Python с PyTorch 2.11.0 / torchvision 0.26.0 только для CPU, PyInstaller, модели, сжатие установщика).
3. Где появится установщик, зависит от того, содержит ли он валидированную модель: репозиторий публичный, а артефакт рабочего процесса может скачать любой вошедший в GitHub пользователь. **Полный вариант:** только из сборки по тегу `v*` — он прикрепляется к *черновику* GitHub Release этого тега (**Releases** → черновик → `Sentinel Medical AI Setup 1.1.0.exe`; черновик видят только пользователи с правом записи в репозиторий; опубликованный релиз этого публичного репозитория может скачать кто угодно, поэтому не публикуйте черновик, в котором остаётся полный установщик). Повторный запуск рабочего процесса тега, релиз которого уже опубликован (или *Run workflow* на этом теге), ничего не загружает и завершается ошибкой: полный установщик попадает только в *черновик* релиза — соберите его под новым тегом `v*`. Он никогда не загружается как артефакт рабочего процесса: *Run workflow* на ветке с отмеченным `include_validated_model` — это репетиция (сборка и дымовой тест выполняются, ничего не загружается, сводка задания сообщает об этом). **Клинический вариант:** на странице запуска **Artifacts** → `sentinel-windows-x64-NO-VALIDATED-MODEL` — zip-архив с файлом `Sentinel Medical AI Setup 1.1.0.exe` (electron-builder записывает его в `desktop-app/release/`). Артефакты хранятся только **1 день** (`retention-days: 1`): скачайте установщик сразу после сборки и сохраните его вместе с документами выпуска.
4. Без валидированной модели артефакт называется `sentinel-windows-x64-NO-VALIDATED-MODEL`. Если вы собрали его намеренно (`include_validated_model` не отмечен), это **клинический вариант**: передавайте его только вместе с пакетом модели и лицензией для конкретного ПК (§ 5.4, `docs/vendor_provisioning_ru.md`). Если вы ожидали полный вариант из сборки на ветке, секрет `MODEL_BUNDLE_TOKEN` отсутствует или не даёт чтения репозитория моделей (13.2) — такая установка сообщает `/health` → `"status": "degraded"`, пока не импортирован пакет. Сборка по тегу `v*` в этом случае завершается ошибкой.

### 13.2 Секреты: валидированная модель и подпись кода

| Секрет | Назначение | Если не задан |
|---|---|---|
| `MODEL_BUNDLE_URL` | Необязательный запасной вариант: URL zip-архива, в корне которого лежит папка `brain_triage_finetuned/` (`MANIFEST.json`, `config.json`, `preprocessor_config.json`, `model.safetensors`), или его многочастного `manifest.json` — например, закрытый ресурс GitHub Release (`https://api.github.com/repos/<owner>/<repo>/releases/assets/<id>`) или предподписанная ссылка объектного хранилища. `packaging/fetch_model_bundle.py` читает его, только когда репозиторий моделей не задан (например, на ПК сборки); рабочий процесс всегда находит модель по идентификатору, поэтому этот секрет **больше не нужно менять при каждом выпуске модели**. Из какого бы источника ни пришла модель, после скачивания каждый файл заново хешируется и сверяется с `MANIFEST.json`, а замороженный сервер обязан вернуть `"status": "ok"` в дымовом тесте. | В CI ничего не меняется. |
| `MODEL_BUNDLE_TOKEN` | **Единственный секрет, от которого зависит модель:** токен с правом чтения закрытого репозитория моделей (fine-grained PAT, *Contents: read*). Репозиторий задаёт переменная репозитория `MODEL_BUNDLE_REPO` (если не задана — `SHAXZODBR/SIAA-models`). С этим токеном задание находит релиз `brain-triage-<identity12>`, идентификатор которого закреплён в собранном коде (`src/inference/validated_metrics.py`), и скачивает его `manifest.json` — при выпуске модели ничего менять не нужно. | Сборка на ветке: громкое предупреждение в журнале и сводке задания; установщик собирается **без** валидированной модели триажа. Сборка по тегу `v*`: завершается ошибкой. |
| `WIN_CSC_LINK`, `WIN_CSC_KEY_PASSWORD` | Сертификат Authenticode (`.pfx`: строка base64 или URL) и пароль к нему; electron-builder подписывает установщик и исполняемый файл приложения. | Неподписанная сборка: при первом запуске Windows SmartScreen показывает *«Система Windows защитила ваш компьютер»* (**Подробнее → Выполнить в любом случае**); антивирус может поместить файл в карантин. Перед внедрением в клинике подпишите сборку. |
| `CSC_LINK`, `CSC_KEY_PASSWORD` | Сертификат Developer ID для macOS (`.p12`) для задания сборки DMG. | Неподписанный и ненотаризованный DMG (Gatekeeper: правый клик → Открыть). |

Публичные модели (`scripts/download_all_models.py --only brain_tumor_class,chest,chest_checkpoint,generic_processors`) кешируются между запусками; валидированная модель скачивается заново при каждом запуске и никогда не хранится в репозитории. Поэтому выпуск модели не требует изменения секретов: опубликуйте её с помощью `packaging/publish_model_bundle.py`, закоммитьте и отправьте изменения `scripts/bump_model_release.py`, затем отправьте тег `v*`. Сборка по тегу `v*` также запускает восстановление с `--require-newest`: она завершается ошибкой, если в репозитории моделей есть более новый выпуск модели (выпуск `brain-triage-*`, созданный позже того, который закреплён в коде), — обычно это тег, отправленный раньше коммита `scripts/bump_model_release.py`; отправьте этот коммит и поставьте тег на него. Чтобы намеренно пересобрать более старую модель, задайте переменной репозитория `MODEL_BUNDLE_ALLOW_OLDER` значение `1` (сборка тогда только предупреждает), а после сборки удалите эту переменную. Чтобы повторить сборку для Windows вручную, выполните `packaging\build_backend.ps1` и `packaging\smoke_backend.ps1` на ПК с Windows и Python 3.11, затем `npm run build:win` в папке `desktop-app\`.
