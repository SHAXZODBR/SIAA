# SIAA — Sentinel Medical AI · Руководство по установке и администрированию (ИТ-служба клиники)

Версия 1.0.0 · Редакция документа 2026-09

Документ предназначен для ИТ-администратора клиники. Руководство для врачей — `user_manual_ru.md`.

---

## 1. Архитектура в одном абзаце

Всё работает на **одном компьютере клиники** (рабочая станция рентгенолога или небольшой сервер рядом с ней):

- **Настольное приложение** (Electron + React) — пользовательский интерфейс. В собранном дистрибутиве оно само запускает сервер ИИ.
- **Сервер ИИ на Python** (FastAPI, PyTorch), слушает **127.0.0.1:8000**. Читает DICOM, запускает панель детекторов головного мозга, формирует черновики заключений, хранит исследования, подписанные заключения и журнал аудита в локальной базе SQLite.
- **Папка моделей** — файлы весов, поставляемые с установкой, только для чтения.
- **Ollama** с языковой моделью Gemma 3 на **localhost:11434** — используется только для текста заключений, перевода и вкладки «Спросить ИИ». Необязательный компонент: без него сервер использует фиксированные шаблоны.

Подключение к интернету не требуется и не используется. Ничего никуда не выгружается.

```
экспорт с томографа / USB / сетевая папка → Приложение → 127.0.0.1:8000 сервер ИИ → SQLite + журналы (папка данных)
                                                                 └→ localhost:11434 Ollama (только текст заключений)
```

## 4. Полностью автономная работа

- Сервер по умолчанию работает в **автономном режиме** (`SENTINEL_OFFLINE=1` при любом запуске, кроме режима разработчика). Hugging Face и transformers переводятся в offline-режим при импорте; **ни одна модель никогда не скачивается во время работы**.
- Поэтому все модели должны находиться в папке моделей до первого использования. Отсутствующая модель не роняет сервер: `/health` сообщает, что она не загружена, с причиной *«model missing — run scripts/download_all_models.py --only <key> on a machine with internet and copy models/ here»*.
- Облачные языковые модели отключены (`SENTINEL_ALLOW_CLOUD_LLM` не задана). Текст заключений формирует Ollama на localhost или шаблоны.
- Если папку моделей вы готовите на машине **с** интернетом, выполните там `python scripts/download_all_models.py` и скопируйте получившуюся папку `models\` на ПК клиники.

## 5. Первый запуск

### 5.1 Учётная запись администратора

При самом первом запуске создаётся учётная запись `admin` (роль *admin*):

- Если при первом старте сервера задана переменная окружения **`SENTINEL_ADMIN_PASSWORD`**, её значение становится паролем администратора.
- Иначе генерируется **случайный одноразовый пароль**, который печатается **один раз**: в консоль сервера и, строками уровня WARNING, в файл журнала `<папка данных>\logs\sentinel_ГГГГ-ММ-ДД.log` (в собранном дистрибутиве — также в `<папка данных>\logs\backend.log`). Ищите баннер *FIRST-RUN ADMIN ACCOUNT CREATED (one-time password)*.
- В обоих случаях учётная запись получает флаг **требуется смена пароля**: при первом входе открывается форма смены пароля, и до замены пароля ничего другого не работает (в приложении — минимум 8 символов).

Не оставляйте одноразовый пароль в файлах, доступных другим. Строка журнала — единственное место, где он хранится.

### 5.2 Мастер первичной настройки

При первом запуске приложение открывает мастер **«Первичная настройка»** (повторно: *Настройки → Клиника → Запустить настройку снова*):

1. **Язык** — язык интерфейса и язык заключений по умолчанию (RU / UZ / EN).
2. **Клиника** — название (обязательно; печатается в шапке каждого PDF), адрес, телефон.
3. **Сервер ИИ** — адрес сервера; оставьте `http://127.0.0.1:8000`, если сервер работает на этом ПК. Мастер показывает текущее состояние сервера.
4. **Лицензия** — отпечаток компьютера и импорт `license.dat` (§ 5.3).
5. **Поддержка** — e-mail/телефон, который врачи видят в каждом баннере ошибки и на экране входа. Укажите здесь свою службу поддержки.

[Скриншот: мастер первичной настройки, шаг 3 «Сервер ИИ» с зелёным статусом]

### 5.3 Активация лицензии

При первом запуске сервер ничего не блокирует: **без действующей лицензии он работает в демо-режиме — 10 анализов в день**, после чего запросы на анализ отклоняются (HTTP 402) до следующего дня. Подписание и просмотр продолжают работать.

Лицензия — файл **`license.dat`**, подписанный поставщиком по RSA и **привязанный к отпечатку этого компьютера** (имя хоста, ОС, модель ЦП, основной MAC-адрес, идентификатор машины ОС).

1. Получите отпечаток. Либо прочитайте его в *Настройки → Лицензия* (приложение запрашивает сервер ИИ), либо выполните на ПК:
   ```
   cd <установка>\resources\backend
   venv\Scripts\python.exe -m src.utils.license fingerprint
   ```
2. Отправьте строку отпечатка (64 шестнадцатеричных символа) и название клиники поставщику.
3. Сохраните полученный `license.dat` в **папку данных** (§ 6) — через *Настройки → Лицензия → Импортировать license.dat* либо скопировав файл вручную.
4. Перезапустите приложение (оно перезапустит сервер). Проверьте `/health` → `license.mode` равно `licensed`, или что в *Настройки → Лицензия* отображается *Лицензировано*, название клиники и срок действия.
5. Проверить файл вручную: `venv\Scripts\python.exe -m src.utils.license verify --license-file <путь>`.

Лицензия становится недействительной при изменении отпечатка компьютера (новая сетевая карта, переименованный хост, клонированная ВМ) или по истечении срока — причина показывается в *Настройки → Лицензия* и в журнале. Обратитесь к поставщику за перевыпуском; тем временем программа переходит в демо-режим, но не останавливается.

## 6. Папка данных

Всё изменяемое состояние хранится в **одной папке** — никогда внутри папки программы:

| Платформа | Расположение по умолчанию |
|---|---|
| Windows | `%APPDATA%\sentinel-medical-ai\` |
| macOS | `~/Library/Application Support/sentinel-medical-ai/` |
| Linux | `~/.local/share/sentinel-medical-ai/` |

Собранное приложение передаёт серверу собственную папку пользовательских данных через `SENTINEL_DATA_DIR`. **Точный путь сообщает сам сервер**: `GET /health` → `data_dir`, а также *Настройки → Подключения → Папка данных сервера*. В сомнительных случаях ориентируйтесь на этот путь, а не на таблицу.

Содержимое:

| Путь | Что это | Персональные данные? |
|---|---|---|
| `sentinel.db` (+ `-wal`, `-shm`) | База SQLite: пользователи (хеши bcrypt), исследования (поля заголовка DICOM, включая ID/имя/дату рождения пациента), результаты ИИ, **подписанные заключения** (текст, подписант, время, SHA-256, идентификаторы моделей), коррекции, **журнал аудита** | **Да** |
| `logs\sentinel_ГГГГ-ММ-ДД.log` | Журнал сервера, ротация по 10 МБ, сжатие zip, хранение 30 дней. Идентификаторы пациентов вырезаются (§ 7). | Обезличено |
| `logs\backend.log` | Сырой вывод консоли сервера, перехваченный оболочкой приложения | Обезличено |
| `doctor_corrections\` | Дописываемый JSONL с правками врачей к черновикам ИИ (текст, ID исследования, ID пользователя) | Текст заключения |
| `training_corpus\` | **Обезличенные** миниатюры и метки, которые записывает сборщик обучающих данных (без имён, ID и дат рождения) | Обезличено |
| `dicom_cache\` | Временный кеш DICOM | Да |
| `license.dat` | Лицензия, привязанная к машине | Нет |
| `jwt_secret.key` | Секрет, которым подписываются токены входа (права 0600). При удалении все пользователи выходят из системы. | Нет |
| `model_key.bin` | Секрет установки для зашифрованных весов моделей (если выпуск поставляется с зашифрованными весами) | Нет |

Загруженные DICOM-файлы во время анализа записываются во временную папку под именами, выбранными сервером, и сразу после анализа удаляются; сервер хранит поля заголовка и небольшое превью-изображение, а не само исследование.

Сборщик обучающих данных записывает **обезличенные** миниатюры и метки в папку `training_corpus\` внутри той же папки данных (`TRAINING_CORPUS_DIR` в `src/utils/paths.py`) — без имён, ID и дат рождения.

### 6.1 Резервное копирование

База данных хранится **в незашифрованном виде**. Держите ПК на зашифрованном томе (BitLocker / FileVault) и делайте копии так:

1. Закройте настольное приложение (это останавливает сервер) или убедитесь, что анализ не выполняется.
2. Скопируйте **папку данных целиком** (§ 6) на внешний диск или NAS — как минимум `sentinel.db`, `sentinel.db-wal`, `sentinel.db-shm`, `doctor_corrections\`, `license.dat`, `jwt_secret.key`, `logs\`.
3. Храните три копии (локально, на внешнем носителе, вне здания), шифруйте съёмные носители и **ежемесячно проверяйте восстановление** на запасной машине: установите ту же версию, скопируйте папку обратно, запустите, войдите, откройте подписанное заключение.

Есть вспомогательный скрипт (`scripts\backup_restore.py backup --out <папка>`, создаёт `.tar.gz` с контрольной суммой), но он ищет базу в папке `data\` бэкенда; прежде чем полагаться на него, убедитесь, что он действительно захватил вашу папку данных. Простое копирование папки, описанное выше, корректно всегда.

### 6.2 Удаление программы

Деинсталлятор Windows спрашивает, удалить ли папку данных. Отвечайте **Нет**, если только клиника не приняла решение уничтожить записи: подписанные заключения и журнал аудита — медико-юридический архив клиники.

## 7. Журналы и обезличивание

- Журнал сервера (`logs\sentinel_*.log`) содержит ID исследований (UUID, сгенерированные сервером), маршруты, время выполнения, статус загрузки моделей, попытки входа по имени пользователя и ошибки. Глобальный фильтр заменяет очевидные идентификаторы пациентов (`PatientID=…`, `PatientName=…`, даты рождения и DICOM-имена вида `Фамилия^Имя`) на `<redacted>` до записи любой строки. Имена клиентских файлов не журналируются никогда.
- **Журнал аудита** (таблица базы, а также `GET /audit/log` для администраторов, последние 200 записей) фиксирует, кто, что и когда сделал: `login`, `analyze_study`, `view_study`, `sign_report`, `change_password`, `register`, с IP клиента и деталями, такими как хеш заключения.
- Журнал аудита — **цепочка хешей**: каждая строка хранит хеш предыдущей строки (`prev_hash`) и свой собственный (`row_hash`), поэтому удалённая или отредактированная строка разрывает цепочку. `GET /audit/verify` (только администратор) проходит цепочку от начала до конца и возвращает `{ok, rows, checked, head_hash, first_broken}`. Выполняйте его после восстановления из резервной копии и перед передачей базы кому-либо; при `ok: false` запишите идентификатор строки из `first_broken` и сообщите поставщику.
- Само настольное приложение пишет только в свою консоль (инструменты разработчика открыты только в сборках для разработки).

При передаче журналов поставщику отправляйте только `sentinel_*.log` / `backend.log`; никогда — базу данных.

## 8. Обновление приложения и моделей

### 8.1 Обновление приложения

1. Сделайте резервную копию папки данных (§ 6.1).
2. Запустите новый установщик поверх старой версии (Windows) или замените пакет приложения (macOS). Папка данных не затрагивается.
3. Запустите приложение один раз под администратором. База данных **мигрирует автоматически** (добавляются новые столбцы; ничего не удаляется). Проверьте `/health` → `version` и версию на экране входа.
4. Приложение и сервер имеют одинаковый номер версии (1.0.0 в этой редакции); версия печатается в каждом PDF.

### 8.2 Обновление модели — MANIFEST и «выпускной барьер»

Валидированный детектор — это папка `models\brain_triage_finetuned\` с файлами `model.safetensors`, `config.json`, `preprocessor_config.json`, **`MANIFEST.json`** и `study_level_eval.json`.

- `MANIFEST.json` фиксирует **SHA-256 каждого файла весов**. Первые 12 символов хеша `model.safetensors` — это отпечаток модели, который показывает приложение (вкладка «Детали», «Находки» → Модели, каждый PDF). Текущий выпуск: `0d559766ce58…`.
- Перед отправкой модели поставщик обязан пройти **выпускной барьер**: `scripts\eval_study_level.py` проверяет манифест, оценивает модель по исследованиям на отложенном локальном наборе и блокирует выпуск (ненулевой код выхода), если чувствительность на уровне исследования < 0,85 или специфичность < 0,40 в рабочей точке продукта (среднее по 5 центральным срезам, порог 0,50). Полученный `study_level_eval.json` поставляется вместе с моделью.

Установка обновления модели:

1. Остановите приложение.
2. Замените всю папку `brain_triage_finetuned\` на присланную поставщиком (сохраните копию старой).
3. Проверьте хеши сами: Windows `certutil -hashfile model.safetensors SHA256`, macOS `shasum -a 256 model.safetensors`; сравните с `MANIFEST.json`.
4. Запустите приложение; убедитесь, что `/health` → `models.brain_triage.loaded = true`, а после одного тестового исследования — что отпечаток во вкладке «Детали» совпадает с хешем из манифеста.
5. Запишите отпечаток модели и дату в журнал изменений клиники; подписанные с этого момента заключения несут новый идентификатор.

Никогда не редактируйте и не переименовывайте файлы внутри папки модели: сервер загрузит модель, идентичность которой уже не соответствует валидированной.

### 8.3 Зашифрованные веса модели (если выпуск поставляется с ними)

Локально обученный детектор — интеллектуальная собственность поставщика; выпуск может поставлять его **зашифрованным на диске** (AES-256-GCM). В такой папке вместо `model.safetensors` лежат `model.safetensors.enc` и `model.safetensors.enc.meta.json`. Сервер расшифровывает веса при загрузке напрямую в память; открытый текст никогда не записывается на диск установки.

- **Ключ** либо выводится из `model_key.bin` в папке данных (создаётся при первом использовании, режим 0600) и отпечатка машины, либо задаётся через `SENTINEL_MODEL_KEY_HEX`, выданный поставщиком для этой установки. Если `model_key.bin` утерян или отпечаток изменился, веса расшифровать нельзя — `/health` показывает `degraded`; обратитесь к поставщику.
- **Проверка хешей** отличается от шага 3 в § 8.2: `MANIFEST.json` фиксирует SHA-256 **открытого текста** (запись `model.safetensors` — отпечаток, который показывает приложение) и SHA-256 **зашифрованного файла** (запись `model.safetensors.enc`). Сравните результат `certutil -hashfile model.safetensors.enc SHA256` (macOS: `shasum -a 256 model.safetensors.enc`) с записью `.enc`, а `plaintext_sha256` из `model.safetensors.enc.meta.json` — с записью `model.safetensors`.
- Утилита командной строки (из папки бэкенда): `python -m src.utils.model_crypto encrypt <папка_модели>` (веса → `.enc`, открытый текст удаляется), `python -m src.utils.model_crypto decrypt <папка_модели>` (обратная операция) и `python -m src.utils.model_crypto keyinfo` (источник ключа и отпечаток ключа; не сам ключ). `encrypt`/`decrypt` — шаги подготовки выпуска на стороне поставщика; никогда не выполняйте их на рабочем дереве `models\`, только на копии. На ПК клиники обычно нужен только `keyinfo` — по запросу поставщика.

## 10. Диагностика неисправностей

Начинайте с **`GET http://127.0.0.1:8000/health`** (откройте в браузере на ПК; вход не нужен). Ответ:

```json
{ "status": "ok" | "degraded" | "error", "version": "1.0.0", "device": "cpu",
  "auth_required": true, "offline": true,
  "models": { "brain_triage": {"loaded": true, "reason": "…"},
              "brain_tumor_class": {"loaded": true, "reason": "…"},
              "chest": {"loaded": false, "reason": "not loaded"} },
  "llm": { "backend": "ollama" | "template" | null, "reachable": true },
  "license": { "mode": "licensed" | "unlicensed" | "demo" | "dev" },
  "data_dir": "…", "uptime_seconds": 123.4 }
```

| Симптом | Где смотреть | Решение |
|---|---|---|
| На экране входа **Сервер ИИ: не в сети**; красный баннер *Сервер ИИ не запущен* | `/health` не отвечает. `<папка данных>\logs\backend.log` и самый свежий `sentinel_*.log` | Проверьте наличие `resources\backend\run_server.py` и его `venv`; что порт 8000 не занят другой программой; прочитайте последний traceback в журнале. Оболочка перезапускает сервер 3 раза (2 с / 4 с / 8 с), затем показывает окно с путём к журналу. Перезапустите приложение; если не помогло — перезагрузите ПК; затем обратитесь к поставщику с журналом. |
| Баннер *Сервер ИИ работает частично: валидированная модель не загружена* | `/health` → `status: degraded`, `models.brain_triage.loaded: false`, читайте `reason` | Обычно **модель отсутствует**: папки `brain_triage_finetuned` нет, она неполная или перемещена. Восстановите её с установочного носителя / из пакета поставщика и перезапустите. До этого панель выдаёт только результаты со статусом «валидация не завершена» — предупредите врачей не полагаться на них. |
| `models.brain_tumor_class.loaded: false` | В `reason` перечислены проверенные папки | Скопируйте пакет модели (`models\hf\…`) с установочного носителя. Не критично: детектор триажа продолжает работать. |
| В строке состояния **LLM: недоступен**; уведомление *Шаблонный отчёт — ИИ-ассистент недоступен* | `/health` → `llm.reachable: false` | Ollama не запущена или в ней нет модели Gemma: `ollama list`, `ollama serve`, `ollama pull gemma3:4b`. На находки и подписание не влияет. |
| В *Настройки → Лицензия* — **Без лицензии** / **Демо-режим**; анализы останавливаются с «Demo limit reached (10 analyses/day)» | `/license/status` → `info.reason` | `no license file at …` → скопируйте `license.dat` в папку данных; `invalid signature` → файл повреждён или изменён, запросите свежую копию; `bound to a different machine` → изменилось оборудование/имя хоста, отправьте новый отпечаток поставщику; `license expired on …` → продлите. После замены файла перезапустите. |
| Врач не может подписать: *Ваша роль не может подписывать отчёты* | роль в `/auth/me` | Подписывать могут только *radiologist* и *admin*; техники — нет. Пересоздайте пользователя с нужной ролью. |
| *Отчёт на этом языке уже подписан* (HTTP 409) | штатное поведение | Одно подписанное заключение на исследование и язык. Не ошибка. |
| Исследование возвращается со статусом **Нужен просмотр** | Причина показана во вкладке «Находки» | МРТ не головного мозга либо модальность без установленной модели. Исследование читается без ИИ. Не неисправность. |
| Загрузка отклонена: *No readable DICOM file in the upload* | — | Файлы — не DICOM (скриншоты, ZIP, NIfTI). Экспортируйте исследование с томографа/PACS в формате DICOM. |
| Все пользователи одновременно вышли из системы | удалён `jwt_secret.key` или изменён `SENTINEL_JWT_SECRET` | Ожидаемо после такого изменения; пользователи просто входят заново. |
| Забыт пароль администратора | — | Интерфейса сброса нет. Остановите сервер, сохраните копию `sentinel.db` и обратитесь к поставщику за процедурой сброса (новый одноразовый пароль администратора генерируется только при отсутствии учётной записи с ролью admin). |
| Не удаётся экспортировать PDF | уведомление во вкладке «Отчёт» *Не удалось экспортировать PDF* | Проверьте свободное место на диске и права записи в выбранную папку; попробуйте папку «Загрузки». |

Автотесты сервера (`tests\`) поставщик может выполнить по запросу.

## 11. Управление пользователями (администратор)

В этой сборке нет экрана управления пользователями; используйте API с ПК клиники (пример на PowerShell, `curl` работает так же):

```powershell
# 1. вход под admin → токен
$r = Invoke-RestMethod -Method Post http://127.0.0.1:8000/auth/login -ContentType application/json `
     -Body '{"username":"admin","password":"<пароль администратора>"}'
$h = @{ Authorization = "Bearer $($r.access_token)" }

# 2. создать рентгенолога (роли: radiologist | technician | admin)
Invoke-RestMethod -Method Post http://127.0.0.1:8000/auth/register -Headers $h -ContentType application/json `
     -Body '{"username":"ivanova","password":"<временный пароль>","fullName":"Иванова А. А.","role":"radiologist"}'

# 3. список пользователей / журнал аудита
Invoke-RestMethod http://127.0.0.1:8000/auth/users -Headers $h
Invoke-RestMethod "http://127.0.0.1:8000/audit/log?limit=200" -Headers $h

# 4. проверить цепочку хешей журнала аудита (ожидается ok: true)
Invoke-RestMethod http://127.0.0.1:8000/audit/verify -Headers $h
```

У каждого врача должна быть личная учётная запись: подпись под заключением — это подписавшая учётная запись. Пароли хранятся в виде хешей bcrypt; API не может показать их обратно.

## 12. Замечания по безопасности

- **Аутентификация включена по умолчанию** и не отключается без `SENTINEL_DEV_INSECURE=1`, которую нельзя задавать на ПК клиники. Клинические маршруты (`/analyze/study`, `/studies`, `/study/{id}`, `/report/sign`, `/report/save_correction`) требуют bearer-токен; роли проверяются на сервере. `/health` и `/license/status` открыты и не содержат данных пациентов.
- **Без облака.** Сервер никогда не обращается в интернет: автономный режим для моделей, облачный LLM отключён, телеметрия Hugging Face отключена. Единственные сетевые соседи — настольное приложение и Ollama на той же машине.
- **Порты привязаны к localhost** (`127.0.0.1:8000`, `localhost:11434`). Не меняйте хост на `0.0.0.0` и не добавляйте исключений в брандмауэр. Если когда-либо потребуется развёртывание на несколько ПК, используйте TLS (`SENTINEL_TLS_*`) и схему сети, согласованную с поставщиком.
- Страницы документации API (`/docs`, `/redoc`) в эксплуатационных сборках отключены.
- **Шифруйте диск** (BitLocker / FileVault): база SQLite и журналы приложением не шифруются.
- Подписанные заключения защищены от незаметного изменения (SHA-256 текста, подписант, время, идентификатор модели, запись аудита), а журнал аудита — цепочка хешей, проверяемая через `GET /audit/verify` (§ 7), но сам файл базы может отредактировать любой, у кого есть доступ к диску — защищайте учётную запись и диск.
- Загруженные файлы никогда не сохраняются на диске под клиентскими именами; временные файлы удаляются после анализа.
- Заведите каждому пользователю личную учётную запись, удаляйте учётные записи уволившихся сотрудников и не храните одноразовый пароль администратора в общих документах.

## 13. Сборка установщика для Windows

Установщик, описанный в § 3, собирает рабочий процесс GitHub Actions `.github/workflows/build-windows.yml` (репозиторий `SHAXZODBR/SIAA`). Он «замораживает» Python-сервер с помощью PyInstaller (`packaging/build_backend.ps1`), скачивает публичные модели, восстанавливает валидированную модель триажа из закрытого архива, проверяет замороженный сервер по `/health` и затем запускает electron-builder (`npm run build:win`). Тот же рабочий процесс собирает образ диска для macOS (Apple Silicon) на macOS-раннере.

### 13.1 Запуск сборки и получение установщика

1. GitHub → **Actions** → **Build installers** → **Run workflow** (любая ветка) — либо отправьте тег вида `v1.0.0`; сборки по тегу дополнительно прикрепляют установщики к *черновику* GitHub Release.
2. Дождитесь завершения задания *Windows installer (NSIS x64)* (это долго: зависимости Python с PyTorch 2.11.0 / torchvision 0.26.0 только для CPU, PyInstaller, модели, сжатие установщика).
3. На странице запуска: **Artifacts** → `sentinel-windows-x64-full` — zip-архив с файлом `Sentinel Medical AI Setup 1.0.0.exe` (electron-builder записывает его в `desktop-app/release/`). Артефакты хранятся 14 дней.
4. Если валидированная модель была недоступна (см. 13.2), артефакт называется `sentinel-windows-x64-NO-VALIDATED-MODEL` — такую сборку нельзя передавать клинике: каждая установка из неё сообщает `/health` → `"status": "degraded"`.

### 13.2 Секреты: валидированная модель и подпись кода

| Секрет | Назначение | Если не задан |
|---|---|---|
| `MODEL_BUNDLE_URL` | URL zip-архива, в корне которого лежит папка `brain_triage_finetuned/` (`MANIFEST.json`, `config.json`, `preprocessor_config.json`, `model.safetensors`) — например, закрытый ресурс GitHub Release (`https://api.github.com/repos/<owner>/<repo>/releases/assets/<id>`) или предподписанная ссылка объектного хранилища. После скачивания каждый файл заново хешируется и сверяется с `MANIFEST.json`, а замороженный сервер обязан вернуть `"status": "ok"` в дымовом тесте. | Громкое предупреждение в журнале и сводке задания; установщик собирается **без** валидированной модели триажа. |
| `MODEL_BUNDLE_TOKEN` | Bearer-токен для этого URL (закрытый ресурс другого репозитория). Для ресурса, прикреплённого к релизу этого репозитория, автоматически используется собственный токен задания. | Скачивание без аутентификации. |
| `WIN_CSC_LINK`, `WIN_CSC_KEY_PASSWORD` | Сертификат Authenticode (`.pfx`: строка base64 или URL) и пароль к нему; electron-builder подписывает установщик и исполняемый файл приложения. | Неподписанная сборка: при первом запуске Windows SmartScreen показывает *«Система Windows защитила ваш компьютер»* (**Подробнее → Выполнить в любом случае**); антивирус может поместить файл в карантин. | `CSC_LINK`, `CSC_KEY_PASSWORD` | Сертификат Developer ID для macOS (`.p12`) для задания сборки DMG. | Неподписанный и ненотаризованный DMG (Gatekeeper: правый клик → Открыть). |

Чтобы повторить сборку для Windows вручную, выполните `packaging\build_backend.ps1` и `packaging\smoke_backend.ps1` на ПК с Windows и Python 3.11, затем `npm run build:win` в папке `desktop-app\`.
