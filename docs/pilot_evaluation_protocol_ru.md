> **Примечание для рецензента:** клиническую терминологию в этом документе должен проверить практикующий врач-рентгенолог до передачи документа в клинику.

# SIAA — Sentinel Medical AI · Протокол пилотной оценки (2–3 месяца)

Версия 1.0.0 · Редакция документа 2026-09

## 1. Цель

Измерить в этой клинике и на её томографах, насколько флаг ИИ-триажа согласуется с мнением рентгенологов и насколько программа вписывается в рабочий процесс описания — до любого решения о повседневном применении. Пилот **не меняет клиническую помощь**: каждое исследование читает и подписывает врач-рентгенолог ровно так же, как сегодня; вывод ИИ сравнивается уже после этого.

## 2. Область

- **Входит:** МРТ-исследования головного мозга взрослых пациентов, выполненные в период пилота и описанные участвующими рентгенологами.
- **Основной объект оценки:** детектор *Триаж исследования — норма / патология (локальный)* (статус *валидировано*).
- **Вторичные (только описательно):** детектор *Опухоль мозга* (статус *валидация не завершена*), полезность черновиков заключений, доступность системы.
- **Не входит:** КТ, МРТ других областей, детские исследования и любое использование вывода ИИ для пропуска или сокращения описания.
- **Длительность:** 8–12 недель либо до достижения целевого объёма размеченного набора (§ 6) — что наступит позже.

## 3. Роли

| Роль | Обязанности |
|---|---|
| **Руководитель пилота** (ведущий рентгенолог) | Отвечает за протокол, журнал арбитража и итоговый отчёт; разрешает разногласия; сообщает о событиях безопасности. |
| **Участвующие рентгенологи** (≥ 2) | Читают и подписывают как обычно; оценивают флаги ИИ; фиксируют время описания. |
| **ИТ-администратор клиники** | Установка, резервные копии, журнал доступности, обезличенный экспорт в конце. |
| **Ответственный за данные** (может совпадать с руководителем пилота) | Ведёт журнал арбитража; следит, чтобы персональные данные не покидали клинику. |
| **Контакт поставщика** | Обновления модели/приложения (в период измерений — только по согласованию), техническая поддержка, получает только агрегированные показатели. |

## 4. Рабочий процесс

1. **Базовый период (недели 1–2, необязательно, но рекомендуется):** рентгенологи читают и подписывают, не открывая панель ИИ; руководитель пилота фиксирует время описания не менее чем для 30 исследований (§ 7.3), чтобы было с чем сравнивать.
2. **Пилотное описание (каждое исследование):**
   1. Загрузите исследование целиком в Sentinel (рабочий список → Загрузить исследование → Папка). Анализ идёт, пока врач читает.
   2. Рентгенолог читает исследование **как обычно**, пишет заключение (черновик ИИ можно взять за основу и свободно править) и **подписывает** его в приложении.
   3. Только **после подписания** рентгенолог открывает вкладку **Находки** и оценивает каждый флаг ИИ (§ 5). Подписанное заключение — эталон; ИИ его никогда не меняет.
3. **Еженедельно:** руководитель пилота просматривает журнал арбитража, сверяет объём с целевым и фиксирует события безопасности и замечания по удобству.
4. **По окончании:** ИТ-служба готовит обезличенный экспорт показателей (§ 8); руководитель пилота пишет отчёт (§ 10).

Обновление модели или приложения в период измерений обнуляет подсчёт для данной версии модели — именно поэтому отпечаток модели записывается для каждого исследования.

## 5. Оценка каждого флага ИИ одним щелчком

Для каждого проанализированного исследования рентгенолог даёт **одно решение по каждому детектору** после подписания:

| Решение | Значение |
|---|---|
| **Согласен** | Флаг ИИ (или «не отмечено») совпадает с подписанным заключением: отмечено — и в заключении описана значимая патология; либо не отмечено — и заключение «норма» / без значимых находок. |
| **Не согласен** | Флаг ИИ противоречит подписанному заключению: отмечено, но исследование нормальное (ложный флаг), либо не отмечено, но в заключении описана значимая патология (пропуск). |
| **Не применимо** | ИИ не анализировал исследование (отклонено / нужен просмотр), исследование вне области пилота либо заключение неопределённое. Исключается из расчёта чувствительности/специфичности. |

Решение занимает секунды и не требует свободного текста. Занесите его в **журнал арбитража** (таблицу ведёт ответственный за данные; шаблон ниже). Исследование идентифицируйте по **ID исследования**, показанному во вкладке «Детали» приложения (идентификатор, сгенерированный сервером), — **не** по имени пациента.

```
study_id | дата | рентгенолог | модальность | флаг_триажа (да/нет) | решение_триаж (согласен/не согласен/н/п) |
флаг_опухоли (да/нет/нет вывода) | решение_опухоль (согласен/не согласен/н/п) | класс_находки_по_заключению (норма/опухоль/инсульт/атрофия/кровоизлияние/другое) |
черновик_использован (да/нет) | время_описания_мин | отпечаток_модели | комментарий (по желанию, без персональных данных)
```

«Значимая патология» определяется руководителем пилота заранее (рекомендуется: любая находка, меняющая тактику или требующая наблюдения; случайные варианты нормы считаются нормой). Разногласия по решению разрешает руководитель пилота; его решение окончательно и фиксируется.

## 6. Размеченный тестовый набор

- **Цель: ≥ 100 размеченных МРТ-исследований головного мозга, в том числе ≥ 40 исследований, отнесённых к норме** (без значимых находок в подписанном заключении). Нормальные исследования — редкий класс, и именно они определяют точность оценки специфичности; включайте каждое последовательное нормальное исследование, не отбирайте.
- Включайте исследования **подряд** в течение пилота; не выбирайте «интересные» случаи.
- Одно исследование на пациента (если пациент обследован дважды, оставьте первое).
- Набор остаётся внутри клиники; это закреплённый эталон для этой и будущих версий модели.

При 60 патологических и 40 нормальных исследованиях 95 % доверительные интервалы составят примерно ±8–10 пунктов для чувствительности и ±15 пунктов для специфичности — достаточно, чтобы выявить серьёзное отклонение от валидированных значений, но недостаточно, чтобы доказать небольшие различия.

## 7. Показатели для отчёта

### 7.1 Основные (детектор триажа, уровень исследования)

- **Чувствительность** = отмечено ÷ (все патологические, размеченные); **специфичность** = не отмечено ÷ (все нормальные, размеченные); каждая с **95 % доверительным интервалом** (метод Уилсона).
- Положительная и отрицательная прогностическая ценность при наблюдаемой распространённости; общая доля отмеченных.
- Сравнение с валидированными значениями поставщика (чувствительность 0,90, специфичность 0,47 на 178 локальных пациентах) и с порогами выпуска (0,85 / 0,40): укажите, лежит ли **нижняя граница** ДИ пилота выше каждого порога.

### 7.2 Вторичные (описательно)

- Детектор опухолей: число «согласен» / «не согласен»; доля ложных флагов среди нормальных исследований.
- Доля исследований, вернувшихся со статусом «нужен просмотр», и причины; сбои анализа.
- Черновики заключений: % заключений, где черновик взят за основу; % отредактированных (по таблице коррекций сервера).

### 7.3 Время описания

Минуты от открытия исследования до подписания заключения, по каждому исследованию (из журнала описания или по отметкам времени приложения: время анализа и `signed_at`). Приведите медиану и межквартильный размах для базовых недель и для недель пилота.

### 7.4 Система

Доступность в рабочие часы (по журналу ИТ и проверкам `/health`), число перезапусков, медианное время анализа одного исследования.

### 7.5 Безопасность

Любое событие, при котором вывод ИИ мог повлиять на описание в неверную сторону (например, реальная находка понижена после «не отмечено»). Цель — ноль; каждое такое событие описывается в отчёте независимо от исхода.

## 8. Обращение с данными

- Все исследования, заключения, журналы и журнал арбитража остаются **на территории клиники**. Само приложение никогда не передаёт данные.
- Журнал арбитража содержит ID исследований, даты, решения и время — **без имён, ID пациентов и дат рождения**. Храните его в сети клиники с доступом только для команды пилота.
- По окончании ИТ-служба готовит **обезличенный экспорт для поставщика**: агрегированные показатели (§ 7) и, если это допускает соглашение о данных клиники, таблицу журнала арбитража только с ID исследований. Без снимков, без заключений, без файла базы данных.
- Журнал арбитража и отчёт по показателям хранятся вместе с документацией пилота в архиве клиники; подписанные заключения остаются в базе приложения как обычно.
- Поставщик может использовать агрегированные результаты для повторной валидации или дообучения моделей только в рамках действующего соглашения о данных.

## 9. Критерии успеха

Пилот считается успешным, и вопрос о повседневном применении может рассматриваться, если выполнены **все** условия:

1. ≥ 100 размеченных исследований, включая ≥ 40 нормальных.
2. Точечная оценка чувствительности триажа ≥ 0,85 **и** специфичности ≥ 0,40, с указанием ДИ; руководитель пилота оценивает, приемлемы ли нижние границы для целей приоритизации.
3. Ни одного события безопасности, связанного с выводом ИИ.
4. Доступность системы ≥ 95 % в рабочие часы; медианное ожидание анализа приемлемо для рентгенологов.
5. Время описания не хуже базового (по медиане).
6. Оценка рентгенологов (короткая анкета в конце): флаг и черновик полезны или нейтральны, но не вредны.

Если не выполнен критерий 2, модель нельзя использовать для приоритизации в этой клинике до повторной валидации; размеченный набор — именно то, что позволит поставщику её исправить.
