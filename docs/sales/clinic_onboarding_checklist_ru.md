# Чек-лист подключения клиники — пилот Sentinel Medical AI

Версия программы 1.1.0 · Для руководителя проекта со стороны поставщика, руководителя пилота и ИТ-администратора клиники. Отмечайте каждый пункт, ставьте рядом дату и инициалы; заполненный чек-лист храните вместе с документацией пилота. Никогда не записывайте в чек-лист ФИО или ID пациентов.

Ответственные: **П** = поставщик, **К** = клиника (руководитель пилота / заведующий отделением), **ИТ** = ИТ-администратор клиники.

## 1. Подписанное соглашение

- [ ] **П + К** — Соглашение о пилоте подписано после юридической проверки (`pilot_proposal_ru.md`) вместе с приложениями A–D.
- [ ] **К** — Назначена команда пилота: руководитель пилота (старший рентгенолог), не менее двух участвующих рентгенологов, ответственный за данные, ИТ-администратор. **П** — назначено контактное лицо поставщика с телефоном и эл. почтой.
- [ ] **К** — Руководитель пилота письменно определил понятие «значимая патология» (протокол пилотной оценки § 5); рекомендуется: любая находка, меняющая тактику или требующая наблюдения.
- [ ] **К** — Решение по Приложению D зафиксировано: можно ли в конце передать поставщику обезличенный журнал арбитража (только ID исследований)? Да / нет.
- [ ] **П + К** — Согласованы даты установки, обучения и начала пилота.

## 2. ИТ-требования

- [ ] **ИТ** — ПК соответствует § 2 руководства по установке: Windows 10/11 64-bit, процессор от 4 ядер (рекомендуется 8), ОЗУ от 8 ГБ (16 ГБ, если локальная языковая модель работает на том же ПК), от 20 ГБ свободного места на SSD (рекомендуется 50 ГБ), экран 1600×1000.
- [ ] **ИТ** — Операционная система обновлена; шифрование диска (BitLocker) включено; для установки есть учётная запись локального администратора.
- [ ] **ИТ** — Оборудование, имя компьютера и сетевая карта **окончательные** — лицензия привязана к отпечатку машины, который меняется при изменении любого из них.
- [ ] **ИТ** — Выбран источник исследований: PACS через локальный узел Orthanc (томограф или PACS отправляют на него) или папка экспорта DICOM.
- [ ] **ИТ** — Необязательная локальная языковая модель для текста заключений установлена, пока у ПК ещё есть интернет (`ollama pull gemma3:4b`); без неё программа использует шаблоны заключений.
- [ ] **ИТ** — Есть место для резервных копий папки данных (второй диск или сетевая папка внутри клиники).
- [ ] **ИТ** — Подготовлены эл. почта и телефон службы поддержки для шага «Поддержка» мастера первого запуска.

## 3. Установка

- [ ] **П + ИТ** — Запустите установщик Windows. При поставке модели для конкретной клиники это вариант установщика без валидированной модели (имя артефакта оканчивается на `-NO-VALIDATED-MODEL`). Примите медицинский дисклеймер.
- [ ] **ИТ** — Первый запуск: одноразовый пароль администратора найдите в журнале (`<папка данных>\logs\`, баннер *FIRST-RUN ADMIN ACCOUNT CREATED*), войдите и сразу смените его. Храните пароль в хранилище паролей клиники.
- [ ] **ИТ** — Мастер первого запуска: язык, название клиники (печатается в каждом PDF), сервер ИИ `http://127.0.0.1:8000`, контакт поддержки.
- [ ] **ИТ** — Для каждого рентгенолога — личная учётная запись (роль *radiologist*); общих учётных записей нет. Каждый пользователь меняет временный пароль при первом входе.
- [ ] **ИТ** — Записан путь к папке данных (из `/health` → `data_dir`), настроено первое задание резервного копирования.

## 4. Отпечаток машины

- [ ] **ИТ** — Посмотрите отпечаток (64 шестнадцатеричных символа) в Настройки → Лицензия или на установленном ПК выполните `<install>\resources\backend\sentinel-backend\sentinel-backend.exe --print-fingerprint` (для установки из исходного кода — `venv\Scripts\python.exe -m src.utils.license fingerprint`).
- [ ] **ИТ → П** — Отправьте отпечаток и полное наименование клиники поставщику по согласованному каналу. Отпечаток не секретен и не содержит данных пациентов.

## 5. Лицензия и поставка зашифрованной модели

- [ ] **П** — На рабочем месте поставщика подготовьте пакет клиники командой `packaging/provision_clinic.py` (лицензия с ключом модели, пакет модели, зашифрованный для этого отпечатка, README для администратора на русском и английском); выдача записывается в реестр лицензий поставщика. См. `docs/vendor_provisioning_ru.md`.
- [ ] **П → ИТ** — Передайте папку пакета: `license.dat`, `brain_triage_finetuned_<identity>_<fp8>.zip` (`<fp8>` — первые 8 символов отпечатка), `README_admin_ru.txt`, `README_admin_en.txt`. Приложение принимает пакет только на этом ПК и только с этой лицензией. Храните папку конфиденциально: `license.dat` вместе с zip-файлом — это ключ к весам модели.
- [ ] **ИТ** — Настройки → Лицензия → **Импортировать license.dat**; перезапустите приложение; в Настройки → Лицензия видны *Licensed*, название клиента и срок действия.
- [ ] **ИТ** — Настройки → Модели ИИ → **Импорт пакета модели** (администратор), выберите zip. Сервер проверяет обе контрольные суммы и пробно расшифровывает пакет до переключения модели. Всплывающее сообщение показывает идентификатор новой модели: он должен совпадать с идентификатором в README поставщика.
- [ ] **ИТ** — Если импорт завершился ошибкой `license_model_key_missing`, лицензия не была импортирована первой (или приложение не перезапущено): импортируйте `license.dat`, перезапустите, повторите импорт пакета. Если ошибка `bundle_not_for_this_machine`, установлена лицензия не из той же папки или пакет сделан для другого отпечатка: импортируйте лицензию из той же папки и перезапустите; если ошибка остаётся, снова отправьте поставщику текущий отпечаток. При любой другой ошибке: Настройки → О программе → **Экспорт диагностики** и отправьте zip поставщику (данных пациентов в нём нет).

## 6. Проверка

- [ ] **ИТ** — Откройте на ПК `http://127.0.0.1:8000/health`: `status` — ok, `version` — 1.1.0, `license.mode` — `licensed`, `offline` — true, `ai_settings.show_pending_detectors` — false, `models.brain_triage.loaded` — true, `models.brain_triage.identity` совпадает с идентификатором в README поставщика; в Настройки → Модели ИИ в списке *Реестр моделей* модель триажа имеет статус *Валидировано*.
- [ ] **ИТ** — В строке состояния приложения **Сервер ИИ: в сети**; красного баннера нет.
- [ ] **К** — Загрузите одно МРТ-исследование мозга, выбранное руководителем пилота. На вкладке «Находки» есть карточка *Триаж исследования* со значком **Валидировано** и нет карточки опухоли; КТ головы, если её попробовать, показывается как «не проанализировано ИИ».
- [ ] **К** — Выгрузите **черновой** PDF этого исследования и проверьте: бланк клиники, версия приложения 1.1.0, идентификатор модели триажа (12 символов) совпадает с идентификатором в README поставщика, порог решения, дисклеймер и красная строка *AI DRAFT — NOT SIGNED*. Затем уничтожьте тестовый PDF по правилам клиники.
- [ ] **ИТ** — Проверена цепочка журнала аудита (`/audit/verify` возвращает `ok: true`, см. § 11 руководства по установке).
- [ ] **ИТ** — Выполнена первая резервная копия папки данных, восстановление опробовано на копии.

## 7. Обучение рентгенологов (60 минут)

| Минуты | Тема | Материал |
|---|---|---|
| 0–10 | Что программа делает и чего не делает: поддержка решений, каждое исследование подписывает рентгенолог, нет заключения о норме, классификатор опухолей выключен | `one_pager_ru.md`, заявление о назначении |
| 10–20 | Валидированные показатели простыми словами: что означает флаг и чего не означает «не отмечено» | Одностраничник, руководство пользователя § 6.3 |
| 20–35 | Практика: вход, смена пароля, загрузка исследования, вкладка «Находки», значки, «нужен просмотр» и «не проанализировано ИИ» | Руководство пользователя § 2–6 |
| 35–45 | Вкладка «Отчёт»: черновик, правка, три языка, подписание, выгрузка подписанного PDF | Руководство пользователя § 7–9 |
| 45–55 | Разметка: сначала описать и подписать, затем одно решение на исследование (согласен / не согласен / неприменимо), журнал арбитража только по ID исследования | Протокол пилотной оценки § 4–5 |
| 55–60 | Что делать, если сервер ИИ недоступен, куда звонить, как сообщить о подозрении на ложный или пропущенный флаг или о событии безопасности | Руководство пользователя § 10–11 |

- [ ] **К** — Лист присутствия подписан каждым участвующим рентгенологом.

## 8. Начало пилота

- [ ] **К** — Необязательный базовый период (недели 1–2): время описания записано не менее чем для 30 исследований без открытия панели ИИ (протокол § 4, § 7.3).
- [ ] **К** — Журнал арбитража создан в сети клиники, доступ только у команды пилота; столбцы — по шаблону протокола § 5.
- [ ] **К** — В документах пилота записаны дата начала, версия приложения и идентификатор модели триажа.
- [ ] **П + К** — Период измерений заморожен: никаких обновлений модели или приложения без письменного согласия обеих сторон (обновление перезапускает счёт для этой версии модели).

## 9. Еженедельные встречи

- [ ] **К + П** — Каждую неделю, 15–30 минут: сколько исследований размечено и сколько из них нормальных (цели: не менее 100 и не менее 40), разногласия, решённые руководителем пилота, события безопасности (цель — ноль), причины «нужен просмотр», доступность и перезапуски, открытые обращения в поддержку.
- [ ] **П** — На каждое обращение в поддержку ответ дан в течение 1 рабочего дня; ответ отмечен в протоколе встречи.
- [ ] **К** — Протоколы встреч ведутся только с ID исследований — без имён, ID пациентов и дат рождения.

## 10. Отчёт о пилоте

- [ ] **ИТ** — Выгружены агрегированные показатели; обезличенный журнал арбитража (только ID исследований) передан поставщику, только если это разрешает Приложение D. Снимки, заключения и файлы базы данных клинику не покидают.
- [ ] **К + П** — Показатели рассчитаны по § 7 протокола (чувствительность и специфичность с 95 % доверительными интервалами по Уилсону, прогностическая ценность, доля отмеченных, время описания, доступность, события безопасности).
- [ ] **К** — Отчёт составлен по шаблону § 10 протокола и оценён по критериям успеха § 9 протокола; подписан руководителем пилота, заведующим отделением и ИТ.
- [ ] **К + П** — Зафиксировано решение: переход к повседневному применению (коммерческое соглашение), продление пилота или остановка до обновления модели, прошедшего порог выпуска.
